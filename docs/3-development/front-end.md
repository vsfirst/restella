# front-end 구현 노트

설계는 [front-end/README.md](../../front-end/README.md), 화면 설계는 [화면 설계](../2-design/ui/README.md)에 있다. 이 문서는 구현 결과와, 구현하며 정하거나 바뀐 점을 남긴다.

## 결과

- **화면 7개와 대화상자 3개:** S-01~S-07, S-02a(총 재고 조정), S-03a(예약 상세·취소), 충돌 처리 대화상자(해결됨, 옮기기)
- **화면 데이터는 서버에서 props로:** 화면에 필요한 데이터는 모두 서버가 fetch로 받아 위젯에 props로 넘긴다. 변경 뒤와 실시간 알림 뒤에는 `router.refresh()`로 서버가 다시 그린다. 브라우저에서 직접 조회하는 것은 옮기기 대화상자의 재고 하나뿐이다.
- **BFF:** 로그인·로그아웃, `/api/bff/*` 중계(SSE 포함). 토큰은 httpOnly 암호화 쿠키에만 있다.
- **테스트:** 단위 테스트와 Playwright E2E로 "마지막 1실" 시연 시나리오를 검증했다([테스트 결과](../4-testing/test-report.md)).

## 설계에서 바뀐 점과 이유

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| iron-session 설정 위치 | `_app` | `shared/api` (서버 전용 `index.server.ts`) | 화면(`_pages`)이 서버 렌더링에서 토큰을 써야 한다. FSD에서는 아래 레이어가 `_app`을 import할 수 없다 |
| SSE 중계 경로 | 별도 Route Handler | `/api/bff/[...path]` 하나로 일반 요청과 SSE를 함께 중계 | 응답 본문을 그대로 흘려보내면 SSE도 동작한다. 경로(`/api/bff/events/stream`)는 설계와 같다 |
| 결정 대기 3건 | zod, shadcn/ui·TanStack Table, openapi-typescript | 쓰지 않음, 쓰지 않음, `@hey-api/openapi-ts` | [front-end 설계 "정한 것"](../../front-end/README.md#정한-것) |
| S-07 "평균 동기화 지연" | 최근 1시간 평균 | "동기화 완료 n/m", "전송 대기·재시도 n건" | 평균 지연을 주는 API가 없다. 지연은 Prometheus 지표(NFR-05)로 본다 |
| S-04 처리됨 탭 | "처리됨" 하나 | 미처리·옮김·해결됨·취소 탭 | back-end가 상태 하나씩 조회한다. 처리 방식별로 나눠 보는 편이 사후 확인에 낫다 |
| FSD `features` 레이어 | 사용자 행동 6개 | 두지 않음. 각 행동은 쓰는 위젯 안에(로그인 폼은 로그인 화면에) | 모든 기능이 한 곳에서만 쓰였다. 레이어를 오가며 고칠 이유가 없다(사람 결정) |
| FSD `entities` 레이어 | 엔티티 7개 (요청 함수, 타입, 배지) | 두지 않음. 경로·요청·타입·도메인 표시 부품은 `shared` | 경로를 한 파일로 모으고 props로 그리게 바꾸자 엔티티 대부분이 한 줄짜리 포장만 남았다(사람 결정). 파일 38개 → 7개 |
| 서버 데이터 전달 | TanStack Query 캐시로 넘김(HydrationBoundary) | 서버가 fetch로 받아 props로 넘김. 갱신은 `router.refresh()` | 서버가 TanStack Query에 기댈 이유가 없다. props로 바로 그리면 키 맞추기, 캐시 무효화 범위 관리가 사라진다(사람 결정) |
| "더 보기" | 브라우저에서 다음 페이지를 이어 붙임 | `?cursor=` 페이지 이동(서버가 그림) | 화면 데이터를 모두 서버가 그리도록 맞췄다. 링크로 공유할 수 있다 |
| 시간 표시 | "3초 전" 같은 상대 시각 | 서울 기준 절대 시각, 화면을 연 뒤 새로 들어온 충돌은 강조 | 상대 시각은 서버와 브라우저가 그리는 시점이 달라 hydration 불일치가 난다 |

## 구현하며 정한 것

- **Next.js 16.4 기본값:** `create-next-app@16.4.0`으로 만든 템플릿을 먼저 확인하고 그 설정(`cacheComponents`, `partialPrefetching`, `@tailwindcss/turbopack`)을 따랐다. 템플릿이 안내하는 대로 `node_modules/next/dist/docs`의 해당 버전 문서를 읽고 구현했다.
- **세션 읽기 전 `connection()`:** iron-session은 쿠키를 풀 때 현재 시각으로 만료를 확인한다. Partial Prefetching은 쿠키가 있는 요청에서 앱 셸을 미리 렌더링하는데, 이때 현재 시각을 읽으면 Next.js가 오류를 낸다. 그래서 세션은 항상 요청 시점에만 읽는다.
- **로그인 폼은 POST:** JavaScript가 실행되기 전에 제출되면 브라우저 기본 동작(GET)으로 비밀번호가 URL에 실린다. 폼에 `method="post" action="/api/auth/login"`을 두고, BFF가 폼 제출도 받아 303으로 이동시킨다. 이동할 경로(`next`)는 같은 사이트 경로만 허용한다.
- **채널 API는 중계하지 않음:** `/api/bff/channel/*`은 404다. 채널 API는 채널 서명 전용이다.
- **로그아웃은 전체 이동:** 브라우저의 쿼리 캐시와 화면 상태를 확실히 버리려고 라우터 대신 페이지를 새로 연다.
- **Activity와 대화상자:** Cache Components는 이전 화면을 숨겨 두었다가 되살린다. 상세 패널처럼 다시 열려야 하는 상태는 URL(`?id=`)에 두고, 대화상자 열림 상태는 화면 안 상태로 둔다.
